(WHITE BOX --- Developer Jobs)
First Level of Software Testing is **UNIT TESTING**

-- comes under white box testing
-- what is unit -- its a single component or module of a software 
-- for  I.E --> Email --> indox and compose is a single module or component and like wise --> spam, sent, deleted, etc
-- conduct on single program or single module by Developer 
-- types
1. basic path testing
2. control structure testing 
3. conditional coverage
4. loop coverage
5. mutation testing


Integration Testing (white box testing by developer)

-- IT is performed b/w 2 or more modules
-- focused on data communication b/w multiple modules 
-- types of integration testing 
1. incremental IT
2. Non-Incremental IT

1--> inclemently adding modules and checking the data flow b/w modules 

1--  types  or approach
1.1 top down
1.2 bottom up

top down -> incremental integration testing -> inclemently adding modules and checking the data flow b/w modules and ensure the module added is the child of previse model 

bottom up ->   incremental integration testing -> inclemently adding modules and checking the data flow b/w modules and ensure the module added is Parent of previse model 

IMP

SANDWICH/ HYBRID Approach 
-- its a combination of top down and bottom up 

NON INCREMENTAL INTEGRATION TESTING 
-----------------------------------
we integrate all module at one single shot and check the data flow b/w the modules

drawbacks ----

1. we might miss data flow b/w some modules 
2. if u find defect u can't understand what is the root Cause of defect 

SYSTEM TESTING
----------------

* testing over all functionality of the application with respect to client requirements  (not touching code) 
* ITS BLACK BOX TESTING TECHNIQUE
* this test is conducted by Testing team 
* After completion of unit and integration then start system testing 3rd testing technique 
* we should know the customer requirement before start system testing 
* system testing focus on 
	1. User inter face testing (GUI)
	2. Functional testing
	3. non functional Testing
	4. usability testing

Usability testing -- > how friendly is your application 

USER ACCEPTANCE Testing --> (UTA)

1. alpha testing -- user/customer will do the testing in development environment

1. GUI (Graphical User Interface)

- its a process of testing the user interface of the application or software (frontend part) 

GUI Testing check list

1. testing size, position, width, Hight of the elements
2. testing of the error message that are getting displayed. (exceeding limit in text box)
3. testing the different sections of the screen. 
4. testing of the font whether its readable or not. (check the type and size and diff color)
5. testing of the screen in different resolutions with the help of zooming in and zooming out.
6. testing the color of the fonts. 
7. testing whether the image has good clarity or not. 
8. testing the alignment of the image.
9. testing of the spelling.
10. the user must not get frustrated while using the system interface.
11. testing whether the interface is attractive or not
12. testing of the scrollbars according to the size of the page if any.
13. testing of the disabled fields if any.
14. testing of the size of the image. (should not be big size)
15. testing of the headings whether it is properly aligned or not.
